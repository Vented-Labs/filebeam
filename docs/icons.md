# Icons policy

All first-party UI artwork uses the reviewed Iconsax Free **Twotone** subset in `icons/approved.json`. The source is pinned to `iconsax@0.1.1` and its package integrity in `package-lock.json`; `scripts/generate-icons.mjs` deterministically creates the private Vue, PHP, and Filament Blade registries from that source.

Use `Icon` in Vue and `<x-filebeam-icon>` in Blade. Their names are closed by the generated catalog. Icons inherit `currentColor`; use `size` for dimensions and `label` only for meaningful icons. The default is decorative. Do not add raw SVG, icon-package imports, style/pack props, slots, or direct registry imports.

`npm run check:icons` first verifies generated source integrity, then checks every reviewed workspace dependency declaration against `icons/dependency-inventory.json`. It also fingerprints the complete canonical npm and Composer resolved `{lock path or package name: version}` inventories, so a lock-only package addition or version change fails review. The unused `blade-ui-kit/blade-heroicons@2.7.0` Composer dependency is explicitly recorded as a Filament transitive exception. Adding, removing, or changing any dependency requires an explicit inventory review; this is intentionally broader than a package-name blacklist.

The policy parses TypeScript/JavaScript imports, exports, dynamic imports, CommonJS `require`, JSX, and Vue SFC script/template blocks. It rejects foreign catalogs, direct generated/catalog imports outside the renderer boundary, raw or programmatic SVG, SVG image references, and HTML injection APIs. It also rejects CSS SVG/data URLs, masks, and icon fonts. PHP catalog rendering is rejected even when `Iconsax` is imported under an alias. The only raw SVG exemptions are the generated registries and `Icon.vue`; `FilamentIcons.php` is allowed only to contain the exact first-party Heroicon migration map needed to replace legacy Filament references. Brand/tenant logos, favicons, and PWA marks remain asset exemptions because they are identity artwork, not UI icons. Third-party identity marks that must render through the icon registries live under `brandIcons` in `icons/approved.json`: the Linux mark for the CLI platform picker and the `social-*` platform marks used by the admin-managed community links, which are taken from Simple Icons (CC0 1.0). The checker's `brandIdentityNames` list is closed, so adding a mark means reviewing both the manifest entry and that list.

The checked production source scope is `ui/src`, `backend/app`, `backend/resources/js`, `backend/resources/css`, `backend/resources/views`, `scripts/og`, `vite.config.ts`, and `backend/vite.config.ts`. The generated Blade SVG directory is closed: every SVG there must be named by `approved.json`. The manifest source package, version, tarball integrity, and Twotone style are immutable policy values; the checker independently derives the generated registry digest from the installed, lock-pinned source. The pinned package mis-keys a few Twotone variants (for example `global` sits under `null`); such icons are declared as `{source, variant}` objects in the manifest, and both scripts reject any variant that lacks the Twotone opacity group. The production Docker frontend stage copies these policy inputs and runs `npm run check:icons` before its backend workspace build.

Filament uses the same catalog through its Blade icon factory, alias mappings, loading-indicator binding, and a compiler replacement for direct Blade defaults. PHP tests check installed aliases and direct references so upgrades require a mapping review. Currently unused `RichEditor` and `Wizard` controls are blocked by a regression test until their vendor inline SVG rendering is explicitly integrated. They are not exceptions permitting another icon source. Browser-native control indicators and structural CSS decoration are not icon packs.

Require the CI checks for merges and review changes to the policy scripts, approved catalog, dependency inventory, and exemptions. Local checks cannot prevent someone deliberately changing the enforcement rules themselves.

Run `npm run generate:icons` after changing the approved subset, update the reviewed dependency inventory when dependencies change, then run `npm run check:icons` and `npm run test:icons`. The checker is a structural guard, not a renderer or visual review: avoid encoded, generated, or remote artwork outside these boundaries even where static analysis cannot infer its purpose.
